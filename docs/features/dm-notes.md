# Feature: เมนู DM + โน้ตเนื้อเรื่อง (v0.10.0)

ที่มา: [`../conversations/2026-10-16-dm-notes.md`](../conversations/2026-10-16-dm-notes.md)

## เมนู DM (ฝั่งข้อมูล ในหน้าเล่น)
- แผง DM เปลี่ยนเป็น **รายการเมนู** (หัวข้อคลิกเปิด/ปิด, เปิดได้ทีละหัวข้อ, จำหัวข้อล่าสุดใน localStorage): **ฉาก/แมพ** (อัป, กริด, เลือกฉาก) · **หมอก** · **NPC** · **เนื้อเรื่อง**
- **ให้ของ (GrantPanel)**: ยังอยู่รอบนี้ (เป็นหัวข้อเมนู) → รอบ roster ย้ายไปการ์ดโปรไฟล์ผู้เล่นแล้วลบหัวข้อนี้

## โน้ตเนื้อเรื่อง
- เห็น/แก้ได้เฉพาะ **DM + co-DM** — server ไม่ส่งโน้ตให้ผู้เล่นเลย (กรองต่อ connection ใน state; ผู้เล่นไม่มี field `notes`)
- ใช้ได้ทุกสถานะห้อง (lobby, creating, playing) — DM เตรียมเรื่องก่อนเริ่มเกมได้; หน้า lobby/creating ของ DM มีปุ่มเปิดโน้ตด้วย
- โน้ต = `{id, title (1–80), body (≤ 20000), updatedAt}`, สูงสุด 200 โน้ต
- Events (DM/co-DM): `note.add {title}` → ต่อท้าย · `note.update {id, title, body}` · `note.remove {id}` · `note.move {id, index}`
- **บันทึกถาวร**: `data/notes.json` (โฟลเดอร์จาก flag `-data`, ค่าเริ่มต้น `data/` ข้าง working dir; gitignore) — เขียนแบบ atomic (ไฟล์ชั่วคราว + rename) ทุกครั้งที่เปลี่ยน, โหลดตอน server เริ่ม; ไฟล์เสีย → log error แล้วเริ่มว่าง (ไม่ทับไฟล์เดิม: เปลี่ยนชื่อเป็น `notes.json.bad-<random>`)
- ห้าม log เนื้อหาโน้ต (log แค่ "note.update by=<ชื่อ>")
- UI: รายการหัวข้อ + ปุ่ม "เพิ่มโน้ต"; คลิกหัวข้อ → ตัวแก้ไข (ช่องหัวข้อ + textarea ยาว) ขยายเต็มฝั่งข้อมูล, **บันทึกอัตโนมัติ** หยุดพิมพ์ 600ms → `note.update` + สถานะ "กำลังบันทึก…/บันทึกแล้ว"; ลบ (ยืนยันก่อน), เลื่อนขึ้น/ลง
- DM 2 คนแก้โน้ตเดียวกันพร้อมกัน: คนบันทึกหลังสุดชนะ (ยอมรับ) — ระหว่างพิมพ์ไม่เอาค่าจาก server มาทับช่องที่กำลังพิมพ์
- ข้อความ UI ผ่าน i18n (TH/EN)

## Done
Go tests: สิทธิ์ (ผู้เล่นทำไม่ได้), ผู้เล่นไม่ได้รับ notes ใน state, limits, persist + reload จากไฟล์, ไฟล์เสีย · e2e: DM เพิ่มโน้ต พิมพ์ → รีสตาร์ท server ไม่ได้ (ข้าม) → reload หน้าแล้วโน้ตยังอยู่, ผู้เล่นไม่เห็นเมนูเนื้อเรื่องและไม่มี notes ใน WS message
